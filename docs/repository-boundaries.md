# 저장소 공개 경계

Quilo는 운영 소스와 공개 제품 개요를 분리한다.

| 저장소 | 공개 범위 | 역할 |
|---|---|---|
| `fakeminjun7321/Quilo` | 비공개 | 운영 서버, 웹 UI, 보고서 파이프라인, 문서 엔진, DB와 배포의 기준본 |
| `fakeminjun7321/lab-report-generator-web` | 공개 | 제품 소개, 고수준 아키텍처, 보안 제보 안내 |

## 비공개 저장소에만 두는 항목

- 서버 구현과 배포 설정
- AI system prompt, JSON schema, 후처리·보정 규칙
- 데이터베이스 schema, migration, RPC, 운영 SQL
- 인증, 권한, 관리자, 크레딧·비용, rate limit 구현
- HWPX/DOCX 렌더러, 수식 변환, 이미지 패키징
- Capstone·Excel 파서와 canonical data 보정
- 기관별 템플릿, 실제 샘플, 테스트 fixture
- 키 이름을 넘어 실제 운영 구성을 추론하게 하는 내부 문서

## 공개 저장소에 둘 수 있는 항목

- 제품명, 서비스 URL, 사용자 관점의 기능 설명
- 구현 세부사항을 제거한 고수준 처리 흐름
- 개인정보가 없는 보안 제보 절차
- 공개 자료에 적용되는 라이선스

## 공개 절차

공개 저장소는 비공개 저장소를 자동 미러링하지 않는다. 공개 변경은 아래 순서로 별도 작성한다.

1. 허용 목록에 해당하는 문서만 새로 작성한다.
2. 소스, prompt, SQL, template, fixture, 환경변수 값이 섞이지 않았는지 확인한다.
3. 이메일, 학번, 사용자 입력, 학교 양식 등 개인정보·권리 제한 자료를 확인한다.
4. 공개 저장소의 파일 목록이 `README.md`, `LICENSE`, `SECURITY.md`, 고수준 `docs/` 범위를 벗어나지 않는지 확인한다.
5. 비공개 저장소에서 공개 저장소로 전체 디렉터리를 복사하거나 동기화하지 않는다.

공개 설명이 실제 서비스보다 뒤처져도 운영 코드를 노출하는 것보다 우선하지 않는다. 기능 변경은 먼저 비공개 저장소에서 검증하고, 공개 문서는 필요한 수준으로만 별도 요약한다.
